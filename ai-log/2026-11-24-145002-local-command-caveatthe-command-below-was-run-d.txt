  1. 做法

  1-1 設定：QuoteProperties

  @ConfigurationProperties("quote") 用 record 寫：
  quote.twse.base-url=${TWSE_BASE_URL:https://www.twse.com.tw}
  quote.tpex.base-url=${TPEX_BASE_URL:https://www.tpex.org.tw}
  quote.connect-timeout=3s
  quote.read-timeout=5s
  quote.lookup-timeout=8s   # MarketResolver 整體上限；測試時可以調短
  QuoteConfig 做三件事：
  - 建兩個 RestClient，各自帶 baseUrl 和逾時設定
  - 建一個查詢專用的小執行緒池（2～4 條）
  - 用 @EnableConfigurationProperties 啟用上面的設定

  逾時用 SimpleClientHttpRequestFactory 設定，它是 JDK 內建的 HTTP
  連線，最好解釋。
  另外會在 src/test/resources/application.properties
  加一行註解，說明測試不會用到正式網址。

  1-2 兩支逐檔 client（quote 套件）

  - 共用介面 StockLookupClient，方法是 StockLookup lookupMonth(String code, 
    LocalDate dayInMonth)。
  - TwseStockDayClient、TpexTradingStockClient 各實作一個。
  - 回傳 record StockLookup(Status status, Market market, String name, LocalDate
    tradeDate, BigDecimal closePrice)，Status
    有三種：FOUND／NOT_FOUND／UNAVAILABLE。

  兩個實作上的關鍵點（都會寫進測試）：

  1. 櫃買日期的斜線：如果寫成 .uri("...?date={date}", "2026/11/23")，RestClient
     預設會把變數裡的 / 編碼成 %2F，跟官方範例不同。我改用
     uriBuilder.queryParam(...) 組網址，再用測試 7 直接比對完整網址確認。
  2. 中文亂碼：回應先讀成 byte[]，再交給 Jackson 3 的 JsonMapper 解析，不讀成
     String。官方回應的 Content-Type 如果沒寫 charset，讀成 String
     時中文可能會變亂碼。

  判斷規則：

  ┌────────────────────────────────────────────┬────────────────────────────┐
  │                    情況                    │            結果            │
  ├────────────────────────────────────────────┼────────────────────────────┤
  │ 逾時、連不上、HTTP 4xx/5xx                 │ UNAVAILABLE                │
  ├────────────────────────────────────────────┼────────────────────────────┤
  │ Content-Type 是 text/html，或內容開頭是 <  │ UNAVAILABLE                │
  ├────────────────────────────────────────────┼────────────────────────────┤
  │ JSON 解析失敗、找不到需要的欄位            │ UNAVAILABLE                │
  ├────────────────────────────────────────────┼────────────────────────────┤
  │ 證交所 stat 是 ok（不分大小寫），且 data   │ FOUND                      │
  │ 不是空的                                   │                            │
  ├────────────────────────────────────────────┼────────────────────────────┤
  │ 證交所 stat 含「沒有符合條件的資料」       │ NOT_FOUND                  │
  ├────────────────────────────────────────────┼────────────────────────────┤
  │ 證交所其他 stat 訊息（例如被限流的提示）   │ UNAVAILABLE ←              │
  │                                            │ 我的判斷，請確認           │
  ├────────────────────────────────────────────┼────────────────────────────┤
  │ 櫃買 stat 是 ok，且 tables[0].data         │ FOUND                      │
  │ 不是空的                                   │                            │
  ├────────────────────────────────────────────┼────────────────────────────┤
  │ 櫃買 stat 是 ok，但 data 是空陣列          │ NOT_FOUND                  │
  ├────────────────────────────────────────────┼────────────────────────────┤
  │ 櫃買 stat 不是 ok，或沒有 tables           │ UNAVAILABLE                │
  └────────────────────────────────────────────┴────────────────────────────┘

  解析細節：
  - 解析工具集中在 QuoteParsing：欄位名稱去掉所有空白後再比對；民國日期加 1911
    轉成西元 LocalDate；價格去掉逗號轉 BigDecimal，遇到 -- 或空字串就回 null。
  - 取 data
    的最後一列。日期欄找「日期」，收盤價欄證交所找「收盤價」、櫃買找「收盤」。
  - 證交所的名稱用正規表示式從 title 切出來：代號 + 空白 + (名稱) + 空白 + 
    各日成交資訊，再 trim。切不出來時名稱給 null，但仍然算
    FOUND，因為這一步只需要判斷市場。

  1-3 MarketResolver（quote 套件）

  - 用 CompletableFuture.supplyAsync 在自己的執行緒池裡同時查兩邊。
  - 月初規則集中寫在這裡：查詢日期是 LocalDate.now(clock)；結果是 NOT_FOUND
    時，再用 today.minusMonths(1) 查一次，兩次都 NOT_FOUND 才算
    NOT_FOUND。如果結果是 UNAVAILABLE，就不再查上個月。
  - 整體上限 8 秒：用 allOf(...).get(8s)，時間到時沒完成的那一邊當成
    UNAVAILABLE。
  - 合併規則照你的表。兩邊都 FOUND 時取 TWSE，並記一筆 log.warn。
  - 對外只有一個方法 Market resolve(String code)，例外有兩種：
    - StockCodeNotFoundException：「查無此股票代號：{代號}（上市、上櫃都找不到）
      」
    - MarketUnavailableException：「暫時無法連線官方網站確認代號，請稍後再試」

    寫法和第 2 題的 DuplicateCodeException 一樣，之後 App API 也能共用。

  1-4 套用到新增持股

  - HoldingService.create 的順序：代號 trim、轉大寫（第 2 題已經有）→
    先檢查重複代號 → marketResolver.resolve(code) → 存檔時一併存入
    market。先檢查重複，是為了重複代號時不用白白連外網。
  - HoldingController.create 多接住上面兩種例外，用
    bindingResult.rejectValue("code", ...)
    把訊息顯示在代號欄位下方，不會出現錯誤頁。
  - Market enum（TWSE、TPEX）放在 entity 套件，Holding 加上
    @Enumerated(EnumType.STRING) market。

     做法

     1. 設定（config）

     - QuoteProperties：record，加上 @ConfigurationProperties("quote")。欄位：
       - twse.baseUrl、tpex.baseUrl
       - connectTimeout（3s）、readTimeout（5s）、lookupTimeout（8s）
     - QuoteConfig：
       - @EnableConfigurationProperties(QuoteProperties.class)
       - 兩個 RestClient bean（twseRestClient、tpexRestClient），各自帶
         baseUrl，用 SimpleClientHttpRequestFactory 設定逾時
       - 一個查詢用的固定執行緒池 bean（destroy 時 shutdown）
     - application.properties 加上：
     quote.twse.base-url=${TWSE_BASE_URL:https://www.twse.com.tw}
     quote.tpex.base-url=${TPEX_BASE_URL:https://www.tpex.org.tw}
     quote.connect-timeout=3s
     quote.read-timeout=5s
     quote.lookup-timeout=8s

     2. 逐檔 client（quote）

     - StockLookup record：status（FOUND／NOT_FOUND／UNAVAILABLE）、market、name
       、tradeDate、closePrice，另外提供 notFound()、unavailable()
       兩個工廠方法。
     - StockLookupClient 介面：Market market()、StockLookup lookupMonth(String 
       code, LocalDate dayInMonth)。
     - TwseStockDayClient
       - 網址：/rwd/zh/afterTrading/STOCK_DAY?date=yyyyMMdd&stockNo=&response=js
         on
       - 名稱用正規表示式 代號\s+(.+?)\s+各日成交資訊 從 title 切出，再 trim
       - stat 是 OK 且 data 不是空的 → FOUND；stat 含「沒有符合條件的資料」→
         NOT_FOUND；其他 → UNAVAILABLE
     - TpexTradingStockClient
       - 網址：/www/zh-tw/afterTrading/tradingStock?code=&date=yyyy/MM/dd&respon
         se=json
       - 用 uriBuilder.queryParam 組網址，日期裡的 / 才不會被編碼成 %2F
       - 名稱取最外層的 name（trim）
       - stat 是 ok 且 tables[0].data 不是空的 → FOUND；data 是空的 →
         NOT_FOUND；其他 → UNAVAILABLE
     - 兩支共通：
       - 用 toEntity(byte[].class) 取回應，交給 Jackson 3 的 JsonMapper.readTree
         解析，避免 charset 沒寫時中文變亂碼
       - Content-Type 是 text/html，或內容開頭是 < → UNAVAILABLE
       - RestClientException 或 JSON 解析例外 → UNAVAILABLE
       - 取 data 的最後一列；用欄位名稱找位置（日期、收盤價／收盤）；找不到欄位
         → UNAVAILABLE
     - QuoteParsing：
       - normalizeField：去掉所有空白
       - parseRocDate：民國年 + 1911 轉成 LocalDate
       - parsePrice：去掉逗號轉 BigDecimal；-- 或空字串回 null
       - isOk：比對 stat，不分大小寫
     - JsonMapper 由 Spring Boot 自動提供的 bean 注入。如果 4.x 沒有這個 bean
       型別，就在 QuoteConfig 自己建一個，實作時確認。

     3. MarketResolver（quote）

     - 回傳 record MarketResolution(Market market, String 
       name)；查不到或無法確認時丟例外。
     - 兩支 client 都用 CompletableFuture.supplyAsync(..., executor) 同時查。
     - 每一支的流程：先用 LocalDate.now(clock) 查本月；結果是 NOT_FOUND 時，再用
       minusMonths(1) 查上個月。
     - 整體等待 lookupTimeout：allOf(...).get(...)，時間到時沒完成的那一邊算
       UNAVAILABLE，並 cancel。
     - 合併規則：
       - 證交所 FOUND → TWSE（如果兩邊都 FOUND，log.warn）
       - 否則櫃買 FOUND → TPEX
       - 兩邊都 NOT_FOUND → StockCodeNotFoundException
       - 其他情況 → MarketUnavailableException
     - 兩種例外放在 exception 套件，訊息照題目。寫法參考現有的
       exception/DuplicateCodeException.java。

  跟計畫不一樣的三個地方

  1. MarketResolver.resolve() 直接回傳 StockLookup，沒有另外寫

  先講衝突

  CLAUDE.md 2.1 第 1 條規定：使用者的請求不可以呼叫官方 API，只能讀資料庫裡的行

  「輸入時就顯示名稱」如果每打一個字就查官方，一個代號可能送出十幾個請求，很容易
  被證交所擋（回 403 或 HTML），反而會讓真正的新增也失敗。

  兩種做法

  A. 現在做：游標離開代號欄位時查官方，加上短時間快取
  - 觸發時機：游標離開代號欄位時，或停止輸入 0.5 秒後，而且代號是 4～6
    個英數字才查。用很少量的原生 JavaScript，不加套件。

  - 欄位旁的顯示：
