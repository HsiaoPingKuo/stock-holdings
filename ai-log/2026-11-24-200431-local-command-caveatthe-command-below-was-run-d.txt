  ■ 題目原文                                                                    
  盈虧的意思是「假設現在用收盤價全部賣出，淨賺多少」。規則：                    
  - 手續費：成交金額 × 0.1425%，無條件捨去到元，每筆最低 20                     
  元；買進、賣出各收一次                                                        
  - 證交稅：只有賣出收。一般股票 0.3%，ETF（代號 00 開頭）0.1%；無條件捨去到元  
  - 盈虧：賣出金額 − 賣出手續費 − 證交稅 − 買進金額 − 買進手續費                
  - 收益率：盈虧 ÷（買進金額 ＋ 買進手續費）× 100，四捨五入到小數第二位         
    要求：                                                                      
  1.                                                                            
  清單每一筆顯示盈虧和收益率，頁面最上面顯示總計。台股慣例紅色是賺、綠色是虧。  
  2. 寫單元測試，至少涵蓋下面三個例子。測試不可以真的連到證交所或櫃買中心。     
     | 例子           | 代號 | 張數 | 買進價  | 收盤價  | 盈虧    | 收益率  |   
     | 一般股票       | 2330 | 1    | 1000.00 | 1100.00 | 93,708  | 9.36%   |   
     | ETF            | 0050 | 2    | 150.00  | 145.50  | −10,132 | −3.37%  |   
     | 手續費低於 20 元 | 2363 | 1    | 10.00   | 10.50   | 429     | 4.28%   |

  一、做法

  1. 計算類別（calc，不碰資料庫、不連網）

  ProfitResult（record：只裝資料的不可變類別）
  - 欄位：買進金額、買進手續費、賣出金額、賣出手續費、證交稅、成本、市值、盈虧、
    收益率，全部是 BigDecimal。
  - 沒有收盤價時，只有買進金額、買進手續費、成本有值，其他欄位是 null。
  - 另外提供 hasClosePrice()，判斷有沒有收盤價。
  - 這樣設計的原因：
    - 總計要把「沒有收盤價的成本」也算進去，所以每一筆都要有成本。
    - 第 5 題的 JSON 要輸出 null 欄位，這個型別可以直接對上。

  ProfitCalculator（只有 static 方法，沒有狀態）
  - calculate(String code, long shares, BigDecimal buyPrice, BigDecimal 
    closePrice)：closePrice 可以是 null。
  - returnRate(BigDecimal profit, BigDecimal cost)：設成
    public，總計也用它，收益率的規則只寫一次。成本是 0 時直接回 0.00，不做除法。
  - 費率常數用 new BigDecimal("0.001425") 這種字串寫法。用 double 寫法（new 
    BigDecimal(0.001425)）會帶進浮點誤差。
  - 捨入規則：

  ┌────────┬─────────────────────────────────────────────────────────────────┐
  │  項目  │                             怎麼算                              │
  ├────────┼─────────────────────────────────────────────────────────────────┤
  │ 手續費 │ 金額 × 0.001425 → setScale(0, DOWN) → 跟 20                     │
  │        │ 取大的（先捨去、再套最低 20 元）                                │
  ├────────┼─────────────────────────────────────────────────────────────────┤
  │ 證交稅 │ 代號 startsWith("00") 用 0.001，其他用 0.003 → setScale(0,      │
  │        │ DOWN)                                                           │
  ├────────┼─────────────────────────────────────────────────────────────────┤
  │ 收益率 │ 盈虧 × 100 ÷ 成本，用 divide(成本, 2, HALF_UP) 一步算到兩位小數 │
  └────────┴─────────────────────────────────────────────────────────────────┘

  - 收益率一步算完的原因：先除再乘 100 會多一次捨入，可能讓答案差 0.01。
  - 買進、賣出金額直接用「價格 × 股數」，不另外捨入。價格最多兩位小數（資料庫是
    DECIMAL(12,2)），股數又是 1000 的倍數，算出來一定是整數。
  - 輸入不合理時丟 IllegalArgumentException：股數 ≤ 0、價格 ≤ 0、代號空白。

  2. 總計（calc）

  PortfolioSummary（record）
  - 欄位：總成本、市值、盈虧、收益率、未取得收盤價的筆數。

  SummaryCalculator.summarize(List<ProfitResult>)
  - 總成本：每一筆的成本都加進去。
  - 市值、盈虧：只加有收盤價的。
  - 收益率：呼叫 ProfitCalculator.returnRate(盈虧, 總成本)。
  - 沒有持股時：總成本、市值、盈虧都是 0，收益率是 0.00，不會出錯。

  3. 清單頁

  HoldingListItem
  - 多一個 ProfitResult profit 欄位。
  - 另外加一個 9 個參數的建構子，給 Repository 的查詢語法（JPQL 的 select new 
    …）使用。建構子裡呼叫 ProfitCalculator，股數 = 張數 × 1000，沒有收盤價時傳
    null。
  - 效果：每次讀清單都即時計算，不存進資料庫。第 5 題的 API
    拿到同一個物件，數字就會跟網頁一致。

  HoldingController.showList()
  - 多放一個 summary 到 model：用 SummaryCalculator 加總清單每一列的 profit。

  holdings.html
  - 總計區塊：放在標題和提示訊息下面、「新增持股」上面。
    - 顯示總成本、市值、盈虧、收益率。
    - 有取不到收盤價的持股時，多顯示「N 筆未取得收盤價，不計入市值與盈虧」。
    - 沒有持股時也顯示，內容是 0／0／0／0.00%。
  - 清單在「收盤價日期」後面新增兩欄：盈虧、收益率。
    - 金額用 #numbers.formatInteger(x, 1, 'COMMA')，顯示成 93,708、-10,132。
    - 收益率用 formatDecimal(..., 2, 'POINT') 再加 %。
    - 沒有收盤價時，兩格都顯示「—」。
  - 顏色：
    - 新增 CSS class gain（紅）和 loss（綠），由盈虧的正負決定；等於 0 不上色。
    - 收益率跟著盈虧的顏色，總計也一樣。
    - 不沿用現有的 .error，因為它代表「錯誤」，意思不同。

  ## 盈虧怎麼算

  盈虧的意思是「假設現在用收盤價全部賣出，淨賺多少」。每次打開清單時，用最新的收
  盤價即時計算，不存進資料庫。

  | 項目 | 規則 |
  |---|---|
  | 買進金額、賣出金額 | 買進價（或收盤價）× 股數（1 張 = 1,000 股） |
  | 手續費 | 成交金額 × 0.1425%，**無條件捨去到元**，每筆最低 20
  元；買進、賣出各收一次（先捨去再套最低：14.25 → 14 → 20） |
  | 證交稅 | 只有賣出收。一般股票 0.3%，ETF（代號 `00` 開頭，例如
  0050、00631L）0.1%；無條件捨去到元 |
  | 成本 | 買進金額 + 買進手續費 |
  | 盈虧 | 賣出金額 − 賣出手續費 − 證交稅 − 買進金額 − 買進手續費 |
  | 收益率 | 盈虧 ÷ 成本 × 100，**四捨五入**到小數第二位（負數也一樣：−3.375% →
  −3.38%） |

  例子：2330、1 張、買進價 1,000.00、收盤價 1,100.00

  - 買進 1,000,000，手續費 1,425；賣出 1,100,000，手續費 1,567（1,567.5
  捨去），證交稅 3,300
  - 盈虧 = 1,100,000 − 1,567 − 3,300 − 1,000,000 − 1,425 = **93,708**
  - 收益率 = 93,708 ÷ 1,001,425 × 100 = 9.357… → **9.36%**

  ### 總計

  | 項目 | 算法 |
  |---|---|
  | 總成本 | 每筆成本加總，**沒有收盤價的也算進去**（買進的錢已經花出去了） |
  | 市值 | 每筆「收盤價 × 股數」加總，沒有收盤價的不算 |
  | 盈虧 | 每筆盈虧加總，沒有收盤價的不算 |
  | 收益率 | 總盈虧 ÷ 總成本 × 100，四捨五入到小數第二位（不是把每筆收益率相加）
  |
