  二、規則對應的方法（HoldingReplayCalculator）

  規則: 入口：檢查輸入、重播、組結果
  方法: public static HoldingReplayResult replay(String code, List<TradeInput>
    trades, List<DividendEventInput> events, BigDecimal closePrice)
  ────────────────────────────────────────
  規則: 同一天：除權息 → 買進 → 賣出；同類依 id
  方法: 依日期分組（TreeMap）後逐日處理；交易依 (date, BUY 在前, id) 排序
  ────────────────────────────────────────
  規則: 可參與股數 = 處理到那一刻的股數；同一天多個事件都用配股前的股數
  方法: applyDividendDay(...)：先記下當天開始時的股數，所有事件都用這個數字，配
  股最後才加
  ────────────────────────────────────────
  規則: 成交金額元以下捨去
  方法: tradeAmount(price, shares) → setScale(0, DOWN)
  ────────────────────────────────────────
  規則: 手續費、證交稅
  方法: 直接呼叫 ProfitCalculator.fee()、ProfitCalculator.transactionTax()
  ────────────────────────────────────────
  規則: 買進
  方法: applyBuy(...)：總成本 += 成交金額 ＋ 手續費
  ────────────────────────────────────────
  規則: 賣出：超賣檢查、按比例扣成本、已實現損益
  方法: applySell(...)：先乘再除（總成本 × 賣出股數 ÷
    持有股數），只捨入一次，小數 10 位、HALF_UP；股數歸零時總成本強制設為 0
  ────────────────────────────────────────
  規則: 現金股利、配股
  方法: cashDividend(...)（DOWN 到元）、stockDividend(...)（÷1000 後 DOWN
    到整股）
  ────────────────────────────────────────
  規則: 「無法取得」不計入，但明細要有
  方法: applyDividendDay 裡判斷 source
  ────────────────────────────────────────
  規則: 未實現損益
  方法: unrealized(...)：市值（收盤價 × 股數，元以下捨去）− 賣出手續費 −
    證交稅 − 總成本
  ────────────────────────────────────────
  規則: 顯示時才捨入
  方法: toYuan()（元，HALF_UP）、averageCost()（2 位，HALF_UP，從 10
    位小數的成本直接算，只捨入一次）
  ────────────────────────────────────────
  規則: 含息總報酬
  方法: 捨入後的已實現 ＋ 捨入後的未實現 ＋ 累計現金股利；未實現是 null 時也回
    null

  每次呼叫都用新的區域變數重新算，不留任何狀態，所以同樣的輸入不管算幾次，結果都
  一樣。

  四、文件矛盾或沒寫清楚的地方（需要你決定）

  1. 股數是 0、又沒有收盤價時，未實現損益是 0 還是 null？ 第 9 節 D
