  為什麼這樣設計：
  - 主鍵用流水號 id，不用代號。 App 1.0 修改、刪除都靠 id。Part B
    如果允許同一個代號有多筆，也不用動主鍵。
  - code 存成字串，0050 開頭的 0 才不會掉。
  - buy_price 用 DECIMAL(12,2)，對應 Java 的 BigDecimal，不用 double。
  - 約束都自己取名字。 不取名的話 H2 會自動產生名字。Part B
    如果要拿掉「同代號一筆」的限制，新的 migration 才能用名字刪掉它。

    a. Bean Validation 檢查欄位格式。
    b. Service 存之前先查有沒有重複，有就在表單顯示「2330 已在持股中」。這句和
       API 規格的錯誤訊息一樣，第 5 題可以共用。
    c. 資料庫的 UNIQUE 約束當最後一道防線，處理兩個請求同時送進來的情況。這時也
       轉成同一個錯誤，不會出現 500。
