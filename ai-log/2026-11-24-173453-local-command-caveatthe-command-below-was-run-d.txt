     Context

     第一階段已能判斷上市／上櫃並存名稱。這一步讓清單顯示「官方已公布的最近一個
     交易日收盤價」：
     使用者打開清單只讀資料庫（不打官方），由背景排程在官方公布後一小時內把收盤
     價寫進 quote 表；
     官方連不上時清單照常顯示「未取得」。分支：feature/q3-quote-cache。

     已確認的決定（使用者回覆）：
     - 批次回 HTML → 當成被擋：該市場冷卻 30
       分鐘，這一輪不退回逐檔（同一台主機，再打只會被擋更久）。
       404／500／逾時／找不到收盤表／格式不符 → 才退回逐檔。
     - 舊持股（market 是 NULL）補市場：啟動時補，排程每一輪也檢查。

     ---

     一、做法重點

     1. QuoteHttp 要能分辨「被擋」（修改第一階段）

     目前 QuoteHttp.getJson 把所有失敗都變成
     Optional.empty()，分不出被擋。改成回傳
     HttpJsonResult(Outcome outcome, JsonNode json)，Outcome = OK / 
     BLOCKED（403、429、HTML）/ FAILED（其他）。
     - StockLookup.Status 新增 BLOCKED。MarketResolver.decide
       的「其他情況→無法確認」本來就涵蓋，新增持股的行為不變。
     - 既有測試 被擋403_UNAVAILABLE、回傳HTML_UNAVAILABLE（兩支逐檔
       client）改成預期 BLOCKED。
     - StockLookupClient 新增 default 方法 lookupLatest(code, 
       today)（先查這個月、查不到再查上個月），
       把 MarketResolver.lookupRecentMonths
       的邏輯搬過去，讓逐檔備援也能共用（避開月初陷阱）。

     2. 批次 client（新）

     - MarketCloseBatchClient 介面：market()、BatchQuoteResult 
       fetchDay(LocalDate date)
     - BatchQuoteResult(Status, LocalDate tradeDate, List<DailyQuote> 
       quotes)，Status = OK / NO_DATA / FAILED / BLOCKED
     - DailyQuote(code, name, market, priceDate, closePrice)
     - TwseMiIndexClient：用欄位名稱找同時有「證券代號、證券名稱、收盤價」的表；
       stat 不是 OK → NO_DATA。
       日期：MI_INDEX 資料列沒有日期欄，改從該表標題「115年11月23日
       每日收盤行情…」取民國日期；取不到才用最外層 date（西元）。
     - TpexOtcClient：tables[0]，欄位「代號、名稱、收盤」（沿用
       QuoteParsing.indexOfField 去空白比對）；
       tables[0].date 民國日期；資料列空的 → NO_DATA；stat 不是 ok 也當
       NO_DATA（和證交所一致，log 記下 stat）。
     - 共用 QuoteParsing（千分位、-- → null、民國年）。代號超過 10
       字的列略過、名稱超過 50 字截斷，避免一列壞資料讓整批寫入失敗。

     3. quote 表與寫入規則

     - V3__create_quote.sql（照任務規格；CHECK 約束命名 ck_quote_market）。
     - entity/Quote、repository/QuoteRepository。
     - service/QuoteService.upsert(Collection<DailyQuote>)：一次載入既有資料，逐
       筆比較——
       沒有→新增；新的 price_date ≥
       舊的→更新；比舊的還舊→跳過。回傳實際更新筆數。updated_at 用 clock。

     4. 清單頁（只讀資料庫）

     - dto/HoldingListItem（id, code, name, market, lots, buyPrice, closePrice,
       priceDate）。
     - HoldingRepository 新增 JPQL：Holding h left join Quote q on q.code = 
       h.code，名稱 coalesce(h.name, q.name)，依代號排序。
     - HoldingService.findAllForList() 取代 findAll()；controller 的 showList
       改用它。
     - holdings.html 加「收盤價」「收盤價日期」兩欄：closePrice 為 null →
       「未取得」、日期空白；有值 → 千分位兩位小數。

     5. 新增持股與即時提示（HoldingService）

     - create：MarketResolver FOUND → 同一交易內 quoteService.upsert
       寫入該檔行情，再存持股；
       MarketUnavailableException → 查 quote 表，有→用 quote 的 market、name
       新增；沒有→照原本丟錯、不儲存。
       StockCodeNotFoundException 不退回 quote（官方明確說沒有）。
     - lookupStock：先查 quote 表，有就直接回傳（不打官方）；沒有才走
       MarketResolver。

     6. 背景更新（每個市場一條獨立的鏈）

     - service/MarketRefreshState：每個市場一份——doneDate（今天拿到了）、usedPer
       Stock（上一輪用逐檔）、cooldownUntil。
     - service/RefreshSchedule（純計算，好測）：nextRun(now, state)：
       - 週六日、已 done、已過 15:40 → 下一個平日 13:40；13:40 前 → 今天 13:40
       - 冷卻中 → 冷卻結束時間（超過 15:40 就改隔天）
       - 13:40～14:30 → 60 秒 ± 0～5 秒（毫秒級隨機，非整數秒）；上一輪用逐檔 →
         10 分鐘
       - 14:30～15:40 → 10 分鐘；算出來超過 15:40 → 改隔天 13:40
     - service/QuoteRefreshService.runRound(market, trigger)：
       - 排程：批次查今天 → OK：upsert，資料日期 = 今天就
         done｜NO_DATA：不算錯｜BLOCKED：冷卻 30 分｜
         FAILED：逐檔查「該市場有持有、且 quote 沒有或 price_date <
         今天」的代號（lookupLatest），
         請求間隔隨機 3.2～5.8 秒，遇到 BLOCKED
         立刻冷卻並停止；全部都是今天的資料 → done。
       - 啟動：從今天往前，最多 10 天，找到第一個有資料的交易日（每次請求間也隔
         3.2～5.8 秒）；FAILED → 逐檔；BLOCKED → 冷卻。
       - 每輪最後：補舊持股的市場（見下），並寫一行
         log：來源、市場、批次／逐檔／無、更新筆數、資料日期。
       - 整輪包 try/catch，例外只寫 log。
       - 等待用注入的 Pause 介面、隨機用注入的 RandomGenerator，測試不必真的等。
     - service/HoldingBackfillService（決定：啟動＋每輪都檢查）：market 是 NULL
       的持股 →
       先查 quote 表（批次寫入後大多查得到，不用打官方）→ 查不到才呼叫
       MarketResolver（請求間隔同上）；
       用 tryLock
       避免兩個市場同時跑；任一市場冷卻中就不呼叫官方；MarketUnavailable →
       這次停止，下輪再試。
       Holding 新增 fillMarket(market, name)（只在 market 為 NULL 時才填）。
     - service/QuoteRefreshScheduler：監聽
       ApplicationReadyEvent，開關關閉就什麼都不做；
       開啟時對兩個市場各排一個「立即執行的啟動輪」，每輪結束（finally）用
       RefreshSchedule 算下一次再 schedule，
       所以同一市場不會兩輪重疊，也不需要固定 cron。不使用 @EnableScheduling。
     - QuoteConfig：新增兩個批次 client bean、專用 ThreadPoolTaskScheduler（3

     ## 收盤價怎麼更新
     - 清單上的收盤價來自本機資料庫的行情快取，打開清單不會向官方查詢。
     - 伺服器啟動時，會在背景向官方查一次最近一個交易日的收盤價（例如週六啟動拿
     到週五的資料），不影響啟動速度；官方連不上也能正常啟動。
     - 交易日（週一到週五，台北時間）13:40～15:40
     由背景排程更新：上市、上櫃各自查詢。
       13:40～14:30 約每 60 秒一次，14:30～15:40 每 10
     分鐘一次；拿到當天資料後該市場當天就停止。
       （依實測：官方約 13:50～14:02 公布當天收盤價。）
     - 全市場批次查詢失敗時，改成逐檔查詢有人持有的股票；被官方擋下時該市場暫停
     30 分鐘。
     - 非交易時段若官方或測試伺服器的資料有變動，要等下一個交易日 13:40
     之後，或重新啟動伺服器才會更新。
     - 關閉背景更新：環境變數 `QUOTE_REFRESH_ENABLED=false`。

     ## 清單顯示「未取得」的情況
     - 還沒拿到這檔股票的行情（例如剛啟動、官方連不上，或這檔不在官方清單中）。
     - 官方顯示該交易日沒有成交（收盤價是 `--`）。

  修改的檔案
  - service/HoldingService.java
    - create() 的順序：
      i. 先檢查代號是否重複。
      ii. 查 quote 表，有這個代號就直接用表裡的市場、名稱新增，不呼叫官方。
      iii. quote 表沒有，才問 MarketResolver。查到時把最近交易日和收盤價一起寫進
           quote 表，新增完清單馬上看得到價格。
      iv. 官方連不上時，維持原本的錯誤「暫時無法連線官方網站確認代號，請稍後再試
          」，持股和快取都不儲存。
    - lookupStock()（輸入代號時的即時提示）：一樣先查 quote 表，沒有才問官方。
    - 建構子多注入一個 QuoteService。

  測試
  - HoldingServiceTest 新增 4 個：
    - 快取有這個代號 → 新增成功，MarketResolver
      完全沒被呼叫（verifyNoInteractions）。
    - 快取沒有 → 問官方，並把收盤價、收盤日、最近交易日寫進快取。
    - 快取沒有、官方又連不上 → 顯示錯誤，持股和快取都沒有寫入。
    - 即時提示：快取有這個代號時直接回傳，不呼叫官方。
  - NoOfficialCallTest 新增 1 個：啟動整個程式，在快取有 6488
    的情況下打即時提示和新增，四支官方 client 和 MarketResolver 都沒有被呼叫。

  測試時遇到一次失敗，已修好：「即時提示先查快取」那個測試第一次沒過。原因只出在
  測試環境，正式執行不受影響：

  - lookupStock 標了 NOT_SUPPORTED，會先暫停外層的交易（transaction），改用另一
    條資料庫連線去讀快取。
  - 這個測試整個包在一個測試用交易裡，寫進去的快取資料還沒
    commit，另一條連線看不到。
  - 正式執行時，快取資料早就 commit 了，不會有這個問題。

  修法：只讓這個測試不包交易，測完自己刪掉資料。這是我寫測試時沒想到交易的範圍，
  不是產品程式的 bug。

  第 7 步：單一市場的行情更新流程

  這一步做的是「某個市場跑一輪更新時要做什麼」。什麼時候跑（13:40～15:40、間隔、
  休市日、伺服器啟動時）是第 8 步。所以這一步 commit
  後啟動伺服器，還不會自動更新行情。

  新增的檔案
  - service/QuoteRefreshService.java：一輪的流程。
    - 排程輪：先查今天的批次。
      - 拿到資料 → 整批寫入快取；資料日期是今天，這個市場今天就算完成。
      - 沒有資料 → 不算錯誤，等下一輪。
      - 被擋 → 冷卻 30 分鐘。
      - 失敗 → 改用逐檔。
    - 啟動輪：從今天往前找，最多 10 天，找到最近一個有資料的交易日。
    - 逐檔：只查「這個市場有人持有、而且快取裡最近交易日還不是今天」的代號。
      - 一次只送一個請求，請求之間隨機等 3.2～5.8 秒。
      - 被擋就停止這一輪並冷卻。
      - 持有的代號全部拿到今天的資料，才算完成。
    - 每輪最後都會補舊持股的市場，並寫一行 log，例如 行情更新 來源=排程 
      市場=TWSE 方式=批次 更新=1394筆 資料日期=2026-11-24。
    - 任何例外都接住並寫 log，不會往外丟。
  - service/MarketRefreshState.java：每個市場各自的狀態，包括今天完成了沒、上一
    輪是不是用逐檔、冷卻到何時。
  - service/HoldingBackfillService.java：補第 2 題舊持股的市場和名稱。
    - 先查快取；查不到才問官方，問官方時請求之間也要等。
    - 任一市場在冷卻時，只用快取補，不問官方。
    - 官方連不上時，這次先停，下一輪再補。
  - service/Pause.java：「等一下再送請求」包成
    interface。正式執行時真的等；測試時只記錄要等多久，不用真的等。

  修改的檔案

  ## 收盤價怎麼更新
  - 清單上的收盤價來自本機資料庫的行情快取，打開清單不會向官方查詢。
  - 伺服器啟動時，會在背景向官方查一次最近一個交易日的收盤價（例如週六啟動拿到週
  五的資料），不影響啟動速度；官方連不上也能正常啟動。
  - 交易日（週一到週五，台北時間）13:40～15:40
  由背景排程更新，上市、上櫃各自查詢：
    13:40～14:30 約每 60 秒一次，14:30～15:40 每 10
  分鐘一次；拿到當天資料後該市場當天就停止。
    （依實測，官方約 13:50～14:02 公布當天收盤價。）
  - 全市場批次查詢失敗時，改成逐檔查詢有人持有的股票；被官方擋下時該市場暫停 30
  分鐘。
  - 排程會讀取證交所的休市日表，事先公布的休市日當天不查詢；休市日表查不到時（例
  如測試伺服器沒有這支 API）當成交易日，照常查詢。
    颱風假等臨時休市不在表裡，那天會查到「沒有資料」，重試到 15:40 為止。
  - 非交易時段若官方或測試伺服器的資料有變動，要等下一個交易日 13:40
  之後，或重新啟動伺服器才會更新。
  - 新增持股時，若行情快取已有這個代號，直接使用快取的市場與名稱，不向官方查詢。

  ## 清單的收盤價怎麼顯示
  - 一般：顯示最近一個交易日的收盤價與日期。

  {成交日} 收盤價」。
  - 顯示「未取得」：還沒拿到這檔股票的行情（例如剛啟動、官方連不上），或這檔股票
  一直沒有成交紀錄。
